# 附近自动添燃料（不浪费）

《饥荒联机版》独立服务器模组，版本 **1.0.0**。在需要燃料的建筑附近放一个箱子，或把燃料丢在地上，即可自动补充。

[Steam 创意工坊](https://steamcommunity.com/sharedfiles/filedetails/?id=3822016512) · [GitHub 源码](https://github.com/NewBoyIsBusy/nearby-autofuel) · [版本下载](https://github.com/NewBoyIsBusy/nearby-autofuel/releases)

创意工坊当前设置为仅好友可见；其他用户可使用 GitHub 安装包。

![自动添燃料：箱子按序取料，不溢出](assets/workshop-preview.jpg)

## 安装和使用

1. 解压发布包，把 `nearby_autofuel` 整个文件夹复制到游戏的 `Don't Starve Together/mods/` 目录。`modinfo.lua` 应直接位于该文件夹内。
2. 在创建或编辑世界时，进入“模组 → 服务器模组”，启用“附近自动添燃料（不浪费）”。
3. 将箱子放在建筑 **8 距离以内（约两块地皮宽）**，按希望使用的顺序放入燃料。也可以直接将燃料放在建筑附近的地面上。
4. 默认在剩余燃料 **≤50%** 时尝试补充，每 **0.5 秒** 检查一次。无需制作新物品。

只需房主或服务器安装；不新增客户端资源。独立服务器的地面、洞穴分片需要分别启用：

```lua
-- 合并到已有 modoverrides.lua 的 return 表中，保留其他模组条目。
["nearby_autofuel"] = {
    enabled = true,
    configuration_options = {
        SEARCH_RADIUS = 8,
        REFUEL_PERCENT = 0.5,
        GROUND_FUEL = true,
        CHECK_INTERVAL = 0.5,
        REFUEL_EMPTY = true,
    },
},
```

## 取料顺序

- **箱子优先，地面其次。** 多个箱子按与建筑的距离从近到远检查；同距离按实体编号稳定排序。
- **箱内严格按槽位编号从小到大。** 原版普通箱子是从左到右、从上到下。空槽、非燃料、建筑不接受的燃料、被原版条件拒收的物品会跳过。
- 找到第一种合适燃料后，如果目前容量装不下，就等待，不越过它使用后面的槽位、其他箱子或地面燃料。前面一格有一叠时，会优先持续取用这一叠。
- 所有箱子都没有合适燃料，才检查地面；地面按距离从近到远，同距离按实体编号排序。
- 每次最多取 **一个** 物品。共用箱子的建筑各自取料，不会重复消耗同一个物品；不保证多个建筑之间的分配顺序。

例如：第 1 格石头，第 2 格木头，第 3 格草。火坑会跳过石头，优先用木头；即使草能装下，只要前面的木头暂时装不下，也会等待木头能够完整加入。

## “不浪费”的含义

按原版 `fueled:TakeFuelItem` 的算法计算单件实际补充量，包括建筑倍率、自定义燃料倍率和潮湿折损；只有缺口足够大时才消耗一件，不让燃料因为超过容量上限而被截掉。

单件补充量超过建筑**全部容量**的物品永远不能无损加入，因此会跳过；零值或负值燃料也会跳过。原版潮湿燃料折损仍然存在，模组不会将湿燃料变成干燃料。

添料调用原版接口，保留点火、声音、发电机宝石槽等回调。拆分物品后还会重新检查；建筑拒收时归还原箱或原地，避免白扣材料。

严格优先级与不溢出的规则不会保证建筑永远不停机。例如，唯一燃料必须等建筑完全耗尽才装得下时，一次性火堆可能先熄灭消失；可改放单件燃料值较小的物品，或调整槽位顺序。

## 支持范围

- 火堆、石头火坑、吸热火堆、吸热火坑、暗夜灯、雪球发射器、薇诺娜普通发电机。
- 薇诺娜宝石发电机：按原版交易检查和空宝石槽补充普通宝石，不把整叠宝石一起消耗。
- 使用原版 `fueled` 组件、带 `structure` 或 `campfire` 标签且可正常加燃料的其他建筑，可自动接入；第三方模组的自定义接口需单独适配。
- 箱子要求是放置在世界中的建筑型储物容器，使用 `chest` 类型，例如普通箱子、龙鳞宝箱及其升级版本。支持非燃料物品与燃料混放。

不会取玩家背包、随身容器、切斯特等生物容器、远程共享容器中的物品，也不会给武器或随身灯具充能。锅等生产容器不会作为箱子使用。已烧毁、正在燃烧、只读或不可交互的箱子不会取料。

自动添料没有玩家施作者，不提供角色技能加成，也不绕过薇诺娜的技能燃料限制。建筑只接受什么燃料，就只会使用什么；箱内能作为燃料的食物或材料也按原版规则处理。

手动关闭且尚有燃料的雪球发射器不会被自动重新打开。默认允许给已耗尽的建筑补充，因此空火坑会重新点燃，耗尽的雪球发射器可能按原版加料回调重新启动；可在设置中关闭“给已耗尽的建筑补充”，或移走附近燃料。

## 可配置项目

| 设置 | 默认 | 选项 |
| --- | --- | --- |
| 取料半径 | 8 | 4 / 8 / 12 / 16 |
| 开始补充的剩余燃料比例 | 50% | 25% / 50% / 75% / 能装下一份就补充 |
| 取用地面燃料 | 开启 | 开启 / 关闭 |
| 检查间隔 | 0.5 秒 | 0.5 / 1 / 2 秒 |
| 给已耗尽的建筑补充 | 开启 | 开启 / 关闭 |

安装后已有建筑也会在下次加载世界时获得自动添料功能。移除模组不改变箱子、燃料或建筑的存档结构。

## 开发与验证

运行时代码只有 `modmain.lua` 和 `scripts/nearby_autofuel.lua`，不覆盖原版组件。测试脚本不进入发布包。

- `tests/run_tests.py`：Lua 5.1 环境加载本工作目录原版 `Fueled`、`Trader` 组件，验证顺序、容量、潮湿倍率、单件扣除、拒收归还、共享取料等 28 项用例。需要 Python 和 `lupa`。
- `tests/run_game_smoke.py`：使用本机 DST 专用服务器引擎，新建独立离线测试目录，临时加载验证副本，结束后删除临时模组，不读写现有世界。结果写入工作目录 `autofuel_test_storage/engine_console.log`。
- 实现依据：本地 `game_scripts_reference/scripts/components/fueled.lua`、`container.lua`、`stackable.lua`、`trader.lua` 以及原版建筑预制物脚本。

在工作目录执行：

```powershell
python nearby_autofuel/tests/run_tests.py
python nearby_autofuel/tests/run_game_smoke.py
```

单独克隆仓库时，在仓库根目录执行 `python tests/run_tests.py`。测试依赖原版游戏脚本：可用环境变量 `DST_SCRIPTS_PATH` 指向自行从游戏安装目录解出的 `scripts` 目录；原版脚本不随本仓库分发。引擎测试可传入游戏目录：`python tests/run_game_smoke.py "你的 Don't Starve Together 目录"`。

封面使用内置图像生成工具制作，原图为 `assets/workshop-cover.png`，创意工坊预览为相同画面的 JPEG 编码 `assets/workshop-preview.jpg`；生成提示词保存在 `assets/cover-prompt.txt`。
